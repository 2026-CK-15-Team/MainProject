# 아트 리소스 목록

> AI로 작성한 문서임. 현재 코드 기준으로 화면에 나오는 것 전부. 지금은 전부 코드가 그린 기본 도형으로 대체 중.
> 규격은 **H 단위**로 적음. 실제 픽셀 = **H × PPU**. **PPU 미정** (아래 0장에서 결정).
> 우선순위: ★★★ 없으면 게임이 안 읽힘 / ★★ 완성도 / ★ 나중

---

## 0. 기준값 (미정 → 정하면 이 표만 고치면 됨)

| 변수 | 값 | 설명 |
|---|---|---|
| **H** | 1 칸 = 1 Unity unit = 플레이어 캐릭터 세로 높이 | 기획서 고정. 모든 판정 반경/사거리가 H 기준이라 아트를 바꿔도 게임 수치는 안 바뀜 |
| **PPU** (Pixels Per Unit) | **미정** | 1H(타일 1장)가 몇 px인지. 모든 스프라이트 임포트 설정에 같은 값 |
| 카메라 세로 시야 | 6H (`GameBalance.Camera.ViewportHeightInH`) | 화면 세로에 타일 6칸 |
| 기준 해상도 | 1920 × 1080 (16:9, 필러박스/레터박스) | 1080p에서 **1H = 180 화면 px** |
| UI 기준 | 1920 × 1080 UI 단위 | UI 리소스는 PPU와 무관, UI px로 적음 (원본은 2배 권장) |

### PPU 후보 (1080p 정수 배율 기준)

카메라 세로 6H 고정이라 1080p에서 1H = 180px. 도트 아트를 선명하게(정수 배율) 쓰려면 180의 약수가 유리함.

| PPU | 1080p 배율 | 1440p 배율 | 느낌 |
|---|---|---|---|
| 18 | x10 | x13.3 | 아주 거친 도트 |
| 20 | x9 | x12 | 거친 도트 |
| 30 | x6 | x8 | 저해상도 도트 |
| **36** | **x5** | x6.7 | 일반적인 도트 (16/32 계열과 비슷한 밀도) |
| 45 | x4 | x5.3 | 촘촘한 도트 |
| 60 | x3 | x4 | 고해상도 도트 |
| 90 / 180 | x2 / x1 | | 일러스트풍 (정수 배율 신경 안 써도 됨) |

> 16, 32는 1080p에서 x11.25, x5.625라 Pixel Perfect Camera 없이 쓰면 픽셀이 뭉개짐 → 도트로 갈 거면 36 / 45 / 60 추천, 일러스트풍이면 64~128 아무거나.
> 아래 "PPU=36 예시"는 감 잡기용 참고값.

| 항목 | 규칙 |
|---|---|

## 1. 타일셋 (층마다 1세트, 층끼리 재사용 가능) ★★★

> 실제 생성 결과 180개 층(십자형 방, 복도 포함)의 모든 칸을 분류해서 **실제로 나오는 모양만** 뽑음. 빠진 모양 없음 (분류 안 되는 칸 0).
> 예시 이미지: `ArtResourceList_TileSample.png` (실제 생성 결과에 칸마다 아래 ID를 붙여 둠)

### 전제 (벽 두께가 바뀌면 개수도 바뀜)

| 항목 | 현재 값 | 타일에 주는 영향 |
|---|---|---|
| 위 벽 두께 | 3칸 | 벽 정면 **2줄** (= 두께 - 1) + 천장 1줄 |
| 아래 벽 두께 | 2칸 | 천장 **2줄**. 바닥 쪽 줄(C_B)은 캐릭터를 가림(충돌 없음, 걸어다님), 바깥 줄(C_Fill)은 충돌 |
| 좌우 벽 두께 | 1칸 | 천장 1줄만 |
| 문/복도 폭 | 2칸 | 한 칸짜리 통로가 없어서 바닥 "막다른 끝" 모양 불필요 |
| 타일 1장 | 1×1 H (PPU × PPU px) | 전부 같은 크기 |

### 화면에서 보이는 단면

```

 C  천장(벽 윗면)  ← 충돌               F  바닥
 W2 벽 정면 윗줄   ← 충돌               C_B 천장: 바닥 위에 겹쳐 그려 캐릭터를 가림 (충돌 없음, 걸어다님)
 W1 벽 정면 아랫줄 ← 충돌               C_Fill 천장 채움 ← 충돌

 좌우 벽 (1칸): C 천장만  /  벽 바깥 빈 공간: C_Fill로 화면 끝까지 (위에서 내려다본 벽 윗면이 이어지는 모양)
 3/4 시점이라 아래 벽은 정면이 안 보이고 윗면(천장)만 보임
```

### 축약안: 32장

벽 끝을 "옆이 벽" / "옆이 개구부" 구분 없이 하나로 그리면 W1·W2 각각 가운데 / 왼끝 / 오른끝 / 한 칸짜리 4장 → **8장** (+ 천장 13, 바닥 10, 틈 1).
개구부 쪽 끝은 문 옆 벽의 옆면이 보이는 자리라, 정확안이 더 입체적임.

| 항목 | 제안 | 확인 결과 |
|---|---|---|
| 천장 | 코너 8 + 직선 4 | 바깥 4 + 안쪽 4 + 직선 4 + **채움 1** (아래 벽 바깥 줄, 벽 너머) |
| 벽 정면 | 높이별 3 | 지금 두께(위 3칸)면 **정면은 2줄** (3번째 줄은 천장). 정면 3줄을 원하면 위 벽 두께를 4로. 줄마다 **양 끝 처리** 필요 (위 표) |
| 바닥 | 17 | **10이면 충분**. 아래쪽 테두리는 아래 벽 천장(C_B)이 덮어서 안 보임. C_B를 반투명으로 할 거면 아래 테두리 3장(F_B, F_BL, F_BR) 추가 = 13 |

### 층별 재사용

- 층마다 타일셋 1세트를 지정 (`FloorConfig`). 같은 세트를 여러 층이 가리켜도 됨
- 색만 바꾸는 층은 같은 그림에 팔레트만 바꾼 세트로 충분

### 코드 연결 (코드 오토타일, 구현됨)

- 타일셋 에셋: `Create > Dungeon > Dungeon Tileset` → 위 ID 그대로 칸이 있음 (툴팁에 ID 표기). `FloorConfig > Tileset`에 넣으면 그 층은 오토타일
- 층을 만들 때 방과 복도의 바닥 칸을 한 장으로 모아서 칸마다 위 표 규칙으로 조각을 고르고, 공용 타일맵 4장(바닥 / 벽(충돌) / 앞면(캐릭터 위, 천장 C_B) / 틈(벽 너머, C_Fill))에 칠함. 방 프리팹 타일맵은 숨기고 판정 데이터로만 씀
- **방 프리팹은 바닥 칸만 정확히 칠하면 됨** (벽은 자동, 어떤 타일이든 상관없음) → 같은 방을 층마다 다른 타일셋으로 재사용
- 비어 있는 칸은 같은 분류의 기본 칸으로 대체 (예: 안쪽 모서리 없으면 가운데) → 아트를 일부만 넣어도 깨지지 않음
- 가운데·틈 칸은 여러 장 넣으면 칸마다 랜덤 (같은 시드면 같은 배치)
- 미방문 룸 가림 덮개는 틈 첫 번째 칸을 씀
- 벽 너머는 층 바닥 바깥 `VoidMargin`(기본 8칸)까지 C_Fill로 칠해서 카메라가 룸 끝에 붙어도 배경색이 안 보임
- 벽 정면/천장 타일은 Tile 에셋의 Collider Type을 **Grid**로 (충돌)
- 비밀 벽이 부서지면 그 층을 다시 칠해서 주변 모양이 맞춰짐
- 테스트 콘텐츠 생성기가 조각마다 테두리 방향을 그린 자리 표시 타일셋(`Generated/Tiles/Test_DungeonTileset`)을 만들어 3개 층에 연결함 → 실제 아트 전에 배치 확인용
